# AHS-ID public web catalog

The public site lives in `apps/web` and is deployed to `https://ahs-id.jenss.me` as a Cloudflare Worker with Static Assets.

## Scope

- Astro static output with React islands for landing search, catalog filters, and `/kalkulator`.
- shadcn-style primitives in `apps/web/src/components/ui`.
- **Unified search index** (DAS-63): multi-kind shards under `apps/web/public/search/` (`manifest.json`, `ahsp.json`, `hsp-jakarta.json`, `resources.json`, `productivity.json`), generated by `scripts/build-web-search-index.mjs` / `pnpm --filter @ahs-id/web build-search-index`.
- Catalog browser **fetches shards** in the browser (no 10k+ entries serialized into HTML props). Filter with `?kind=ahsp-coef|hsp-portal|resource|productivity`.
- National AHSP item pages remain SSG from `catalog.ts` (`/item/[bundle]/[code]/`).
- HSP portal detail: `/hsp/jakarta/[sourceId]/` (badge portal; does **not** call `hitungHSP`).
- AHSP DCKTRP-by-source detail: `/ahsp/sumber/[sourceId]/[code]/`.
- Calculator: `/kalkulator/` uses `@ahs-id/engine-registry` (same package list/loaders as CLI).
- Other routes: `/`, `/bundles/`, `/docs/`, `/metodologi/`, `/tentang/`, `robots.txt`, sitemap.
- The web catalog currently excludes seven ambiguous Cipta Karya rows. This is a web projection rule; source packages remain unchanged.

## Search kinds

| Kind | Badge | Detail |
|------|-------|--------|
| `ahsp-coef` | AHSP nasional / AHSP portal DCKTRP | `/item/…` or `/ahsp/sumber/…` |
| `hsp-portal` | HSP portal | `/hsp/jakarta/{sourceId}/` |
| `resource` | Resource | Anchor on national item (`#tenaga-…` / `#bahan-…` / `#peralatan-…`) |
| `productivity` | Produktivitas | Prefill `/kalkulator/?bundle=…&focus=…` |

## Local development

```sh
pnpm install
pnpm --filter @ahs-id/web build-search-index
pnpm --filter @ahs-id/web dev
pnpm --filter @ahs-id/web test
pnpm --filter @ahs-id/web typecheck
pnpm --filter @ahs-id/web build
```

`predev` / `prebuild` already run the search-index generator.

The production site is configured in `apps/web/wrangler.jsonc`. Cloudflare Workers Git integration is bound to `rachmad-jenss/ahs-id` on the `main` production branch and owns the production build and deploy. Its build gate runs:

```sh
pnpm lint && pnpm typecheck && pnpm validate-data && pnpm validate-bundles && pnpm exec turbo run test --concurrency=1 && pnpm --filter @ahs-id/web... build
```

The deploy command is `pnpm --filter @ahs-id/web exec wrangler deploy --env production`. The GitHub workflow verifies the same commit with build, tests, typecheck, and a Wrangler dry-run; it does not require Cloudflare secrets or perform the live deploy.

## Data boundary

`apps/web/src/lib/catalog.ts` normalizes dynamic HSD and fixed-coefficient item shapes into one display model for national bundles. It does not calculate prices and does not mutate bundle data.

`@ahs-id/engine-registry` is the shared CLI ↔ web package registry (named exports, dynamic `import()` loaders, no Node `fs` on the web path). Production calculations should use the engine packages and the HSD bundle appropriate to the project; HSP portal pages are lookup-only.
